# gpuenable

End-to-end setup to run an OpenAI-compatible LLM on this host with:
- NVIDIA RTX A4500 (20 GB) GPU
- vLLM (Qwen/Qwen2.5-7B-Instruct by default)
- Thin FastAPI gateway enforcing API-key auth on `/v1/*`
- nginx reverse-proxy on a second host IP
- Optional public ngrok tunnel for external requestors

Full operator docs live in [`Continue.md`](./Continue.md). External-requestor API
docs live in [`API-USER-GUIDE.md`](./API-USER-GUIDE.md).

## TL;DR

```bash
# Once: bring up the gateway + nginx + ngrok (boots via rc.local)
./start-gateway.sh
./start-nginx-gateway.sh
docker run --rm -p 4043:4040 -d -it --name apirok \
  -e NGROK_AUTHTOKEN=<token> ngrok/ngrok:latest \
  http http://<host_ip>:80 --url=<your-domain>.ngrok-free.dev

# Then: send prompts
./prompt.sh --api-key=<key> "Who are you?"
# or any OpenAI client pointed at base_url https://<domain>/v1
```

## Security

- The `.api-keys` file is mode 600 and **never committed**. Keys are
  256-bit random hex strings, generated by
  [`./gateway-keygen.sh --add <label>`](./gateway-keygen.sh).
- The host's public address is `192.168.8.62`; the secondary IP
  `192.168.8.10` is added via NetworkManager. httpd is restricted to
  `.62:80` so nginx can own `.10:80`.
- Anyone using the public API only needs the URL and a key. They have no
  visibility into vLLM, the gateway, or this host beyond what their
  requests return.
